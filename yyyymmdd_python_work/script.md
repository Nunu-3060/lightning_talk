# 台本

## 1 表紙

* 挨拶と名乗り
* 本職はテストエンジニア。仕事でも趣味でも Python をよく使う
* 今日は仕事で Python をどう使っているかを紹介する

## 2 目次

* データを扱う・テストを自動化する・伝える、の 3 つの用途を順に話す
* 最後に実務で気を付けていることを話し、まとめる

## 3 なぜ Python か

* 仕事で繰り返す作業の多くは、データ・手作業・文書の 3 つに分けられる
* Python には、どれにも使えるライブラリが揃っている
* 1 つの言語で済むので、作業同士をつなげやすい

## 4 今日の全体像

* 図の上から、テストを自動化する・データを扱う・伝える、の 3 つの章
* 矢印のとおり、用途は互いにデータを受け渡している
* 以降はこの図の部品を 1 つずつ紹介し、最後につなぎ方を見せる

## 5 数値計算・データ処理

* 仕事では流体解析ソフトウェアの解析結果を扱っている
* 解析結果は条件の数だけファイルが増える。1 つずつ表計算ソフトで開いて集計するのは辛い
* コードの例：フォルダ内の CSV ファイルをすべて読み、ケースごとの最大値を出す
* 集計の手順はコードに残るので、後から同じ集計をやり直せる

## 6 可視化

* 数値の羅列のままでは、解析結果は読めない
* 図は平行平板間の流れの流速分布。説明用に作った例で、実際の製品の出力ではない
* コードで描けば、データが変わっても再実行するだけで、同じ体裁の図ができる

## 7 画像処理

* 前のページの図を条件違いで 3 枚作り、Pillow で横に並べた
* 軸の範囲が揃っているので、条件による違いがすぐ分かる
* 図を作るところから並べるところまで、スクリプトでつながる。これが「つなぐ」の最初の例

## 8 テスト実行の自動化

* ここから本職のテストの話
* テストは同じ手順を何度も繰り返す
* 表を見ながら：手作業は手順を飛ばしたり、人によって結果がぶれたりする。スクリプトなら毎回同じで、記録も残る

## 9 API を叩く

* REST API を備えたソフトウェア・サービスなら、画面を操作せずにデータを取得・操作できる
* httpx を使っている
* コードの例：ジョブの状態を取得する。URL は説明用の例
* `raise_for_status` でエラーを例外にしておくと、失敗に気付かず先に進むことを防げる

## 10 コマンド実行

* Python で書かれていないソフトウェアでも、コマンドラインから動くなら subprocess.run で呼べる
* コードの例：解析を実行する。solver は説明用の名前
* `check=True` を付けると、失敗したときに例外で止まる
* 余談：13 ページの画像は、Python から subprocess.run で Chrome を呼んで撮った

## 11 組み合わせ：テストの流れ

* 9・10 ページの部品と、2 章のデータ処理・可視化をつなぐ
* 解析の実行 → 結果の取得 → データ処理 → 合否の判定 → 図の作成、までを 1 本のスクリプトにする
* 人が手を出すのは、スクリプトを実行することと、結果を見ることだけになる

## 12 テスト結果の可視化

* テスト結果は数値の表で見るより、図で見た方が変化に早く気付ける
* 図はバージョンごとの、基準値との誤差。説明用に作った例
* 1.6 で許容値を超えている。並べて見れば、どこで変わったかが一目で分かる
* 2 章の可視化が、テストでもそのまま役に立つ

## 13 ドキュメント作成

* 文書は Sphinx で作っている
* 画像は自分で作った Python 入門の資料の表紙
* Sphinx の文書はテキストなので、コードと同じように差分を取り、変更履歴を残せる

## 14 組み合わせ：図入りの文書

* 図を作るスクリプトと文書のソースを、一緒にテキストとして管理する
* データが変わったら、スクリプトと Sphinx を再実行するだけで、文書の図まで新しくなる
* 図を貼り直す手作業が無くなる

## 15 実務で気を付けていること

* 小さく始める：最初から完璧な仕組みを作らない。繰り返す手順の一部から自動化する
* 同じ入力から同じ出力を得る：テストの結果を信頼してもらうため、途中に手作業を挟まない
* 型ヒントと静的解析：今日の画像を作ったスクリプトも、flake8 と mypy の strict を通している

## 16 自動化すべきか

* 何でも自動化すればよいわけではない
* 図は説明用の例：手作業 1 回 30 分、スクリプトを書くのに 300 分、自動化後は 1 回 2 分
* この例では、約 11 回以上繰り返すなら自動化した方が得
* 頻度と 1 回の手間を見積もって判断する

## 17 まとめ

* Python はデータ・手作業・文書のすべてに手が届く
* 仕事では、流体解析の結果の処理、テストの自動化、文書の作成に使っている
* 持ち帰ってほしいのは「つなぐ」という見方。Python は道具であり、道具をつなぐ接着剤でもある
* まずは身近な繰り返し作業を 1 つ選び、Python にしてみてほしい
